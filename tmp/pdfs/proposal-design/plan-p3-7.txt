3．第 I 段階．ローカル FedPACT プロトタイプ開発
3.1．第 I 段階の目的
既に実施済みの Qwen-3B，NEXAR，LoRA，Flower による server 1，client 2 の FedPEFT 環境を FedPACT 第 1 層の
たたき台として利用する．その上で第 2 層及び第 3 層を追加し，FedPACT の「ラウンドごとの全体処理フロー」を
3〜5 ラウンド連続して実行できる状態を作る．

 第 I 段階の完成イメージ
 この段階では，FedPACT が既存手法より高性能であることを示す必要はない．
 各処理が設計通りに実行され，各 round の入力，出力，モデル状態，損失，評価値及び通信内容を追跡できることを
 完成条件とする．



Step I-A．既存 FedPEFT の固定と再現確認

行うのではなく，最低限の再実行で実装状態を確認する．
1．使用モデル，ライブラリ及びバージョンを記録する．
2．NEXAR 前処理，frame sampling，label mapping を記録する．
3．LoRA recipe を保存する．
4．Flower server 1，client 2 を起動し，FedAvg による global LoRA 更新と次 round への再配布を確認する．
5．同一設定を再実行できることを確認し，round 別の loss，F1，LoRA 更新量及び実行時間を保存する．

候補方式を網羅比較せず，第 II 段階の比較実験を実行できる最小構成を優先する．

Step I-C．1 round 統合及び 3〜5 round 安定動作確認
1．global surrogate LoRA を各 client へ配布する．
2．各 client が private data で LoRA を局所学習し，pre，post 及び delta output を取得する．
3．frequency を含む post only 又は post＋delta prototype と LoRA 更新を server へ送信する．
4．server で global surrogate LoRA を FedAvg 集約する．
5．server seed を retrieval し，必要に応じて transformation して proxy を生成する．
6．proxy pair を構成し，post-logit KL 及び delta error を計測する．
7．proxy pair を teacher として foundation LoRA を更新する．
8．評価結果及び処理時間を保存し，更新後 global surrogate を次 round へ引き継ぐ．
最初は 3 round 連続実行し，状態継承に問題がなければ 5 round まで延長する．ローカル PC 上で 10 round まで延
長することは必須とせず，長い round 系列の確認は第 II 段階以降で行う．

 第 I 段階の完成条件
 3〜5 round 連続実行でき，global surrogate が各 round で更新されて次 round へ正しく配布される．
 private data そのものが server へ送信又は保存されていないことを通信ログ及び server-side file audit で確認できる．
 post-only 及び post＋delta prototype，seed retrieval，proxy transformation，proxy pair，foundation LoRA update が一
 つの round 処理として接続される．
 round，client，prototype 単位で中間結果を追跡でき，同一設定を再実行できる．




4．第 II 段階．基本 FedPACT 予備実験
4.1．目的と位置づけ
FedPACT を GCP へ移行し，surrogate に Qwen2.5-VL-3B，foundation に Qwen2.5-VL-7B 以上を用いる異種モデル構
成で第 1〜3 層を動作させる．この段階では，FedPACT 第 2 層及び第 3 層の基本設計条件を効率的に決定するとと
もに，proxy-mediated transfer の中心仮説がどこまで支持されるかを予備評価する．
実験数を抑えながら因果関係を読み取りやすくするため，各比較軸の全直積を試す factorial experiment は行わない．
前段で選択した条件を後段では固定し，必要な比較だけを順に実施する．

4.2．screening と confirmation
第 II 段階は screening と confirmation の二つの pass に分ける．screening では縮小データと少数 run を用い，
prototype 生成法と prototype 数，transformation set，Qinv 規則等の実装パラメータを固定する．confirmation では，
論文化又は後続の本実験に利用する比較条件だけを full evaluation data で複数 run 実行し，平均と標準偏差を報告で
きる形にする．random seed 数は利用可能計算資源を踏まえて confirmation 開始前に固定する．

4.8．Experiment II-5．Non-IID robustness
Experiment II-1，II-2 及び II-4 で選択した FedPACT 構成を固定し，IID と 1 種類の Non-IID 条件を比較する．client
数及び client data volume は固定し，分布条件だけを変更する．Non-IID は class skew 又は Dirichlet split 等から一方
式を選び，定義を実験開始前に固定する．
global surrogate だけでは一部 prototype を再現できない場合でも，第 II 段階では残差経路を直ちに追加せず，
threshold failure rate，client 別 proxy KL，global surrogate F1 及び foundation ΔF1 として記録する．残差経路は第 III
